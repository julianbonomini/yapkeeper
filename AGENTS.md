# Working on Yapkeeper

## Commits

Use short, plain-language commit subjects, such as `Add session search` or `Fix orphaned session labels`. Describe what changed in words a person would use; omit Conventional Commit prefixes unless the user explicitly requests them.

Never add AI authorship or generation notices to commit subjects, bodies, or trailers. This includes "authored by Codex", "authored by Claude", "generated by", and AI `Co-authored-by` trailers. Preserve the user's configured Git author and committer identity. These rules also apply to commits made through Vago or other tools.

## Product and session data

Read `docs/product.md` before changing product behavior, `GLOSSARY.md` when defining session or location concepts, and `docs/session-formats.md` before working on provider discovery, parsing, or resume.

Provider adapters own format-specific discovery, parsing, and resume arguments. The shared model, search index, and interface consume their results.

Treat provider histories as read-only. Inspect local structure with bounded reads and report schemas rather than private content. Use synthetic or deliberately redacted fixtures in tests; private transcripts, titles, and project paths must stay out of committed files.

Keep the index rebuildable. Store hide/unhide preferences separately so rebuilding the index preserves the user's choices.

## Terminal UI and language

Use the `tui-design` skill for terminal interface design, implementation, and review. Read the reference for the selected ecosystem before making framework-specific decisions.

Prioritize usable startup time, search latency, and responsiveness during indexing. Compare Rust, Go, and TypeScript on representative workloads; distinguish measured results from estimates and minimal runtime measurements from complete TUI behavior. Real-history benchmarks require explicit user authorization, read-only sources, temporary private indexes, and aggregate output. Keep fixtures synthetic or redacted. Read `docs/language-performance.md` when evaluating the language and TUI framework.

The implementation language, runtime, TUI framework, and reuse strategy are open pending benchmarks and a UI prototype. Vago's starter defaults are not project decisions. Review the selected workflow's checks, harness, model, and GitHub steps before running it.
